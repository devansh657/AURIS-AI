# AURIS Sound System

The web shell generates short original sine cues for listening, completion, and warning. One server-owned persistent Windows speech-input broker arbitrates bounded push-to-talk, wake, and interruption sessions. It exposes live hypotheses and capture state only in memory, detaches the microphone after every listen, and gives direct command or interruption requests priority over wake listening. Spoken responses route through one server-owned AURIS Vale broker backed primarily by a local Kokoro fp16 model on ONNX Runtime CUDA. Startup readiness waits for both persistent input and the selected output engine to become warm. Long replies are divided at bounded sentence, clause, or word boundaries; playback starts after the first chunk while the same worker synthesizes one chunk ahead. The same speaker identity is retained while sentence meaning adjusts restrained speed and pause profiles. The broker strips visual markup, invalidates all prefetched audio on replacement or interruption, disables ONNX provider fallback during synthesis, and deletes every temporary PCM chunk after playback. Browser speech synthesis is deliberately disabled so a second voice cannot join the session. If Kokoro CUDA is unavailable at startup, the broker selects Piper and then exact Windows SAPI as startup-only fallbacks; it never switches voices silently during a session. Sound is supplementary; every cue has an equivalent visual and textual state.
